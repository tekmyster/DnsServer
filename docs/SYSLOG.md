# Syslog forwarding

Open **Settings > Logging > Syslog** on the server you want to configure. Enter the collector's hostname or IPv4/IPv6 address, port (default 514), and UDP or TCP transport. Choose system/DHCP logs, security events, and optionally DNS queries, then choose **Save forwarding**. **Send test** queues a test record; confirm receipt on the collector. Refresh shows local send status and queue/drop counts. Read-only users can inspect settings; configuring forwarding and sending tests require Settings and Administration modify privileges on a direct user/API-token session. Cluster service tokens cannot redirect exports.

Messages use [RFC 5424](https://www.rfc-editor.org/rfc/rfc5424). TCP defaults to [RFC 6587 octet counting](https://www.rfc-editor.org/rfc/rfc6587); **Advanced > TCP framing** also offers line delimiting for compatible collectors. Facility defaults to Local 0. The application name is teQtanium, and message IDs identify `system`, `security`, `dns`, or `test`. Headers include a UTC timestamp, server name, and process ID. Messages use UTF-8 with the RFC 5424 message BOM. Embedded CR/LF in system text is escaped to prevent additional line-delimited records.

System logs retain the existing operational/audit/DHCP messages; exceptions have error severity. Security messages contain bounded JSON with event identity, source node, client/query, action, behavior score, device context and up to four matched indicators. Additional matches are counted. Oversize evidence uses a smaller valid JSON record marked `detailsLimited`; complete evidence remains in the security console. DNS query messages contain client address, DNS transport, question/type and response code. DNS forwarding is independent of local query logging and is off by default. Security events are emitted only when the security module generates them; forwarding does not enable security policy or change DNS/DHCP decisions.

UDP and TCP are unencrypted. Select a trusted collector/network; neither authentication nor native TLS is included in this module. The optional upstream Log Exporter app separately supports TLS for DNS query logs. DNS/client/device data is sent only after forwarding is explicitly enabled.

A background worker isolates network I/O from DNS/DHCP processing. The in-memory queue holds up to 1,024 records, each bounded to 8 KiB. Socket operations time out after three seconds; failed connections are retried for subsequent records with a one-second delay. Failed writes, full queues, and discarded queued records are counted as dropped. Records are not stored for replay: restarts, reconfiguration and prolonged outages can lose queued events. A TCP write failure may have an uncertain collector outcome. UDP submission and TCP socket writes do not prove collector receipt. Larger UDP messages can fragment; use TCP when reliable framing and larger records matter.

Settings are local to each node, persisted atomically in `syslog.json`, and included in native backups when **Logging settings** is selected. Restoring them requires Administration modify permission and applies a fresh revision. Cluster configuration transfer and new-deployment migration preserve the destination's own forwarding setup. Existing logging, credentials, ports, DHCP authority and filtering behavior are retained. Forwarding starts disabled on installations without saved syslog settings.

HTTP API: `GET /api/logging/syslog/get` returns settings and health; `POST /api/logging/syslog/set` accepts `settings` JSON and the current `revision`; `POST /api/logging/syslog/test` returns `queued: true` only when the test enters the queue. Queued is not a receipt confirmation. Use the existing bearer authentication contract.

Verification covers real loopback UDP/TCP collectors, both TCP framing modes, Unicode octet lengths, severity, bounded valid security JSON, saved settings, corrupt-config recovery, collector outages, actual DNS/security hooks, permissions, stale writes and native backup/restore. Deployment-specific collector receipt should be confirmed using Send test.
